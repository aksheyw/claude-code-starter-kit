# Every correction becomes a rule

When you correct me, I write the correction down as a file before carrying on.

**Why this exists.** An assistant that forgets a correction makes you repeat yourself forever, and the repetition stays invisible until it has cost you months. Written down, each one becomes permanent. This is what turns a borrowed set of rules into your own.

**How to apply it.**

- Two triggers: you correcting or redirecting me, and me making the same mistake twice unprompted. Correcting me twice on one thing means this rule failed.
- Type `/learn` into Claude Code and I do the filing, into a `lessons` folder I create in the project if it is not there yet. You never need to know which file it belongs in. Plain words work the same way: remember this, learn from that, do not do that again.
- One lesson per correction, never batched. Keep it specific. "Be more careful" is not a lesson. "Show me the number before the conclusion" is.
- Graduation has one test, and it is not simply twice. The second time the same lesson bites in the same project, tighten the lesson you already wrote rather than stacking another one next to it. The second time it bites in a *different* project, it has outgrown the project: ask for it to move to your rules folder, the one you installed these files into, and from then on it loads everywhere. The ladder is correction, then lesson, then standing rule.
- Name the lessons index in your CLAUDE.md (rule 03). That is what gets it opened at the start of every session. A lessons file written and never named is a file nothing reads.
- Date any lesson that names a version of a tool or model, and say what makes it obsolete. Those expire quietly and keep steering the work afterwards.

# Saving is not publishing

*Trigger: work you would hate to lose, or your first publish.*

Saving your work and putting it where others can see it are two different requests. One must never quietly become the other.

**Why this exists.** Saving should be frictionless and always safe. Publishing changes what other people see and can break things. Bundle them and you lose the moment where you decide.

**How to apply it.**

- Saving means a commit: a checkpoint recording where every file stands, with a note on what changed, kept on your machine and shown to nobody. Not the file existing on your Mac, which happens anyway. Say "commit this and note what changed", constantly.
- Commits only exist inside a repository, the store holding every past version. Git makes one, and a folder you created yesterday is not one yet. So ask first: "is this a git repository, and if not, set one up."
- Publishing means a push: sending those commits to the copy other people see. Only when you say ship, publish or release, never as a side effect.
- Before a change spanning more than one sitting, ask for a branch: a labelled parallel copy where work happens while the working version stays untouched. Ask at the start, because moving work onto one later is the risky part.
- Write one publish checklist and run all of it every time. When a check fails, fix the work, never the check.

# Write the project instructions

Every project gets a file called CLAUDE.md at the top of its folder, and writing it is the first thing you do.

**Why this exists.** Claude Code reads CLAUDE.md at the start of every conversation about that project. Without one you re-explain what the thing is and how to run it every time, slightly differently each time, and get a slightly different answer back. Other rules here tell you to open the project instructions before working. This is the rule that creates them.

**How to apply it.**

- Ask for it in plain words: "read this folder and draft a CLAUDE.md at the top of it." Then read the draft and delete anything it guessed at.
- In it: what the project is in one line, how to start it and how to run its checks, what it is built with, the conventions you want held, and anything you have already corrected twice.
- Out of it: anything that goes stale, so no status, no progress, no counts. No long explanations. Nothing secret.
- Keep it short. It is read in full every time, so every line is paid for every time. One page is generous. Past that, move the detail into its own file and name that file here in one line.
- Anything you want opened at the start of every conversation gets named here: your running notes (rule 08), your lessons file (rule 09). Naming it is what makes it load without you having to remember.
- Correct it the moment it is wrong. A stale line here is worse than no line, because it is trusted and invisible.
